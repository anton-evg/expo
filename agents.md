# Агенты проекта

В этом файле описываются агенты, необходимые для работы над проектом.

Для каждого агента указывайте:

- название;
- назначение;
- задачи и ограничения;
- используемые скиллы;
- ожидаемый результат работы.

## SEO-специалист

**Назначение:** отвечает за поисковую оптимизацию сайта.

**Задачи и ограничения:** проводит SEO-аудит, собирает и структурирует семантику, готовит метатеги, контролирует индексацию и технические SEO-параметры. Не изменяет визуальную часть сайта без согласования.

**Используемые скиллы:** `seo-audit`, `ai-seo`, `programmatic-seo`.

**Ожидаемый результат:** рекомендации и внедренные SEO-улучшения с понятным обоснованием.

## Верстальщик (HTML + CSS + JS)

**Назначение:** реализует интерфейс сайта в коде.

**Задачи и ограничения:** создает адаптивную HTML-разметку, стили CSS и интерактивность на JavaScript. Соблюдает дизайн-макеты, семантику, доступность и производительность. Не меняет дизайн-концепцию без согласования.

**Используемые скиллы:**  `web-design-engineer`.

**Ожидаемый результат:** готовые к проверке страницы и компоненты сайта.

## Дизайнер

**Назначение:** формирует визуальную концепцию и интерфейсные решения.

**Задачи и ограничения:** разрабатывает структуру экранов, композицию, типографику, цветовые решения и состояния интерфейса. Передает верстальщику понятные спецификации. Не вносит изменения в код без согласования.

**Используемые скиллы:** `frontend-design`, `web-design-engineer`, `imagegen`.

**Ожидаемый результат:** согласованные макеты и требования к реализации интерфейса.

## Общие требования

### Верстка

- Использовать чистые HTML, CSS и JavaScript без библиотек вроде Bootstrap; для раскладки применять Flexbox и Grid.
- Для каждой секции или экрана создавать уникальный родительский класс и строить CSS-селекторы только внутри него.
- Применять БЭМ (методология именования классов) в формате `block-name__elem-name--mod-name--mod-val`.
- Имена классов писать латиницей в нижнем регистре; слова разделять дефисом.
- Удалять комментарии из итоговых HTML-файлов.
- Выносить все медиазапросы в отдельные подготовленные CSS-файлы.
- Делать изображения и видео адаптивными; проверять отображение при замене на материалы разных пропорций и размеров.
- Для многостраничных сайтов задавать уникальный класс для `body` каждой страницы, использовать отдельные CSS-файлы и ограничивать ими стили страницы.
- Подключать `normalize.min.css`, затем `reset.min.css`.
- Шрифты и глобальные CSS-переменные хранить в `gp-style-core.css`.

### SEO

- Использовать HTML-теги строго по назначению: текстовые теги — только для текста и заголовков; для декоративных элементов — `div` и `span`.
- На странице допускается только один `h1`.
- В документе обязательно указывать `html`, `head`, `body`, `title`, `description`, `lang="ru"`, `content="html"` и `charset="utf-8"`.
- Для действий без перехода на другую страницу использовать `button`, а не `a`.
- Для каждого `img` указывать информативный атрибут `alt`.

### Порядок работы

1. Определить глобальные CSS-переменные: цвета, градиенты, параметры шрифтов и типографики; сохранить их в `gp-style-core.css`.
2. Скачать шрифты в `/assets/fonts/` и подключить их в `gp-style-core.css`.
3. Сверстать UI kit (набор переиспользуемых элементов) из дизайн-макета: стили — в `gp-style-core.css`, разметка — в `ui_kit.html`.
4. После готовности UI kit верстать основные страницы в файлах `*.html`, переиспользуя готовые классы.
